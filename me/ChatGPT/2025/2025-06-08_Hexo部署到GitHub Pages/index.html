以下是将 Hexo 部署到 GitHub Pages 的直截了当步骤，不废话、效率高：

🔑 1. 安装 hexo-deployer-git

npm install hexo-deployer-git --save

该插件允许你用一条命令推送 public/ 目录内容到 GitHub citeturn0search0turn0search7。

⚙️ 2. 配置 _config.yml

在 Hexo 根目录下打开 _config.yml，添加：

deploy:
  type: git
  repo: https://github.com/你的用户名/你的用户名.github.io.git
  branch: main  # 或 gh-pages, master，根据你设定

确保 repo 地址为你的 Pages 仓库，全 HTTPS 链接，有人说 SSH 地址也行（传 token 时）citeturn0search11。

如部署项目页（非用户页），可以改 repo，比如 username/blog.git，branch 依你 GitHub Pages 设置。

🛠 3. 构建 + 部署

执行：

hexo clean
hexo deploy

这会清理旧资源，生成静态文件，并将 public/ 推送到你配置的 branch 上citeturn0search7turn0search0。

📦 4. 检查 GitHub Pages 设置

  • 如果是用户/组织主页（repo 是 username.github.io），默认 Pages 源会部署 main 或 master 分支。
  • 如果你使用 gh-pages 分支或非默认设置，前往：
    Settings → Pages → Build and deployment → Source，选择对应分支（如 gh-pages），然后保存citeturn0search0。

✅ 5. 验证效果

部署后访问：

  • 用户页：https://username.github.io/
  • 项目页：https://username.github.io/项目名/

生效可能需要几分钟。如显示 404，检查是否为：

  • .nojekyll 文件缺失（跳过 Jekyll 的编译）；
  • public/ 没生成 index.html；
  • repo/branch 设置错误。

🚀 进阶：用 GitHub Actions 自动部署

如果你不想在本地执行 hexo deploy，可以设置 GitHub Actions：

  1. 在 repo 根目录下创建 .github/workflows/pages.yml；
  2. 内容参考官方模板，大意：
on:
  push:
    branches:
      - main

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: "20" }
      - run: npm install
      - run: npm run build
      - uses: actions/upload-pages-artifact@v3
        with: { path: public }
  deploy:
    needs: build
    permissions: { pages: write, id-token: write }
    runs-on: ubuntu-latest
    steps:
      - uses: actions/deploy-pages@v4

这套 workflow 会在你 push main 后自动构建并部署到 Pages citeturn0search0。

✅ 核心判断：部署是否真正完成？

要真正部署到 GitHub Pages，你需要确认：

1. 你的 deploy.repo 指向的是哪个仓库 & 分支

例如，如果你 _config.yml 中配置 branch: master，它会将 public/ 内容推送到你指定 repo 的 master 分支，但该分支以前是否存在？是否和 GitHub Pages 设置一致？

2. GitHub Pages 配置是否正确

GitHub 页面默认只部署以下几种情况之一：

  • 如果是 username.github.io 这种仓库，通常部署默认分支即 main（或老项目的 master）；
  • 如果你使用指定分支（如 gh-pages 或 master），需要确认：
    • 仓库设置中 Settings → Pages → Build and deployment → Source 已选择 Deploy from a branch 并指定了正确分支；
    • 保存后页面右上会显示一个部署链接，如 Your site is live at https://username.github.io citeturn0search0turn0search10。

如果你 push 的分支和 Pages 设置不匹配，当然看不到效果。

🛠 接下来建议你做这些：

  1. 确认本地 _config.yml 配置是否和你推的那个分支一致：

    deploy:
  type: git
  repo: https://github.com/fangwilliam9/fangwilliam9.github.io.git
  branch: master  # 或者 gh-pages

  2. 确认远程已有该 master 分支 且包含你希望部署的内容（可以进 GitHub Repo → “Code” 切换分支，查看是否已含 index.html 等）。

  3. 确认 GitHub Pages 设置正确：

    • 进入 Settings → Pages
    • 源：Deploy from a branch
    • 选择你刚推送的那个分支 + 根目录 /（或者 /docs，视配置而定）
    • 保存设置 citeturn0search10

    • 你需要在 GitHub 网站上把那个新分支 Merge 到目标分支；
    • 或者在本地切到那个分支，做 git checkout master && git pull origin master，确保操作流转顺畅。

  fas fa-envelope: 'mailto:fangwilliam9@gmail.com' || 'Email me' || '#4a7dbe'

把每一段都用单引号或双引号包裹，冒号就不会被当成 YAML 语法符号，前端就能正确识别 mailto: 协议。

  - icon: fab fa-github

    color: '#24292e'

    color: '#4a7dbe'

}

  counter-reset: h3;
}

h3 {
  counter-reset: h4;
}

h4 {
  counter-reset: h5;
}

  counter-reset: h6;
}
