✅ 一步步构建：最小版本的键盘监听器

👇 示例代码（你能直接运行它）

from pynput import keyboard

# 定义一个回调函数：每次按键时就会执行它
def on_key_press(key):
    print(f"你按下了: {key}")

# 创建并启动一个监听器
listener = keyboard.Listener(on_press=on_key_press)
listener.start()

# 主线程的其他逻辑（为了不退出，我们手动 sleep）
import time
while True:
    time.sleep(0.1)

✅ 第一波keyword知识扫盲：

🔁 什么是异步监听器（asynchronous listener）？

意思：不阻塞主线程，事件发生时才触发回调函数。

在这个例子里：

  • 程序主线程在 while True 中跑着自己的逻辑（哪怕你不写它也在“空等”）。
  • 当你按键时，pynput 在另一个线程里捕捉事件，然后执行 on_key_press()。

💡 所以叫“异步”：主线程和监听器并行进行，谁也不耽误谁。

🔥 什么是守护线程（daemon thread）？

守护线程是一种后台线程，当所有“非守护线程”都结束后，它会自动被杀死。

在原代码中：

self.daemon = True

意思是：这个监听器线程不是核心线程，主程序退出它就不用管，直接收尸。

📌 常用于：日志记录器、监听器、心跳检测等后台任务。

🧲 什么是钩子函数（hook）？

hook 就是一个你预留出来可以被外部用户赋值的回调函数。

例子：

self.key_hook = lambda *args, **kwargs: True

这段代码的意思是：“我预先定义一个函数变量 key_hook，它现在什么都不干（空函数），但你以后可以替换成你自己的处理逻辑。”

🧱 什么是默认函数占位？

你不清楚用户会不会用某个钩子，所以先填一个默认函数，防止出错。

self.mouse_move_hook = lambda *args, **kwargs: True

👉 这就是默认占位用的：不会报错，但也不会做事。

🛑 什么是线程的中止控制器？

self._stop_event = threading.Event()

它的作用是：你可以随时从主线程通知监听线程：“停下来吧”。

self._stop_event.wait()     # 线程在这里阻塞等待
self._stop_event.set()      # 另一线程可以通过这句让它结束等待

这是一种“线程间通信”的方式。

⛓ 为什么不能在主线程监听？

主线程是程序的核心逻辑。如果你在里面阻塞监听输入：

keyboard.Listener(on_press=on_key_press).join()

那这个线程就卡住了，不能做别的任何事。

📌 所以作者用 threading.Thread 来让监听器在“另一个并发线程”里运行。

🧰 什么叫“用一个类封装另一个类给外部用”？

你看到的结构是这样的：

Sniffer  ---> 内部创建 SnifferThread

📌 意图是“隔离复杂性”。

  • SnifferThread 专注于监听细节
  • Sniffer 提供一个简单易用的接口，让外部用户只关心 .run()、.cancel() 和设置钩子函数

你可以把 Sniffer 看成是“工程版遥控器”，你不用懂内部电路，只要按按钮就行。
